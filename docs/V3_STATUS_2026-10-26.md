## Föreslaget nästa arbete (minsta säkra diff, en i taget, godkännande per punkt)

Prioriterat efter integritetsrisk, användarnytta och kostnad. Inget av detta är påbörjat.

### Förslag 1 – Dagboksbilder via signerade URL:er (P0, användarnytta)

**Varför först:** fyller V3:s P0 och lagar sannolikt trasiga bilagor för befintliga användare.

**Tänkt diff (ca 4–5 filer):**
- `src/routes/api/diary/upload/+server.ts`: returnera lagringssökvägen i stället för `getPublicUrl`.
- Ny serverväg (t.ex. `/api/diary/image-url`) eller utökad befintlig laddare: verifierar att sökvägen börjar med `<user.id>/`, skapar `createSignedUrl(path, 3600)`. Bakåtkompatibel: härleder sökvägen ur gamla `…/object/public/diary-images/<path>`-värden.
- `src/routes/dagbok/checkin/+page.svelte`: hämtar signerad URL innan `<img>` renderas (samma mönster som video, rad ~974).
- `supabase/diary_image_url.sql` (eller ny migration): spegla produktionen – `public=false`, ta bort `diary_images_select_public`, ägarpolicy för select. **Körs inte** utan separat beslut.

**Testplan:**
- Enhetstester: sökvägshärledning från gammal publik URL; ägarkontroll (annan användares sökväg → 403); signerad URL begärs aldrig utan session.
- Regression: `upload` returnerar inte längre en publik URL; inga `getPublicUrl`-anrop mot `diary-images` (källkontroll).
- Manuellt med godkänd testidentitet i testmiljö: ladda upp, visa, radera konto. Ingen användares bild öppnas.
- `npm run check`, `npm run test:unit`, `npm run build`, CI inkl. `test:browser`.

### Förslag 2 – Ta bort hälsoämnet ur `guide_view` (P0, liten)

- Diff: `src/routes/guider/[pillar]/[guide]/+page.svelte:95-97` – skicka inte `pillar.slug` som `category` (och överväg att inte skicka guidens slug).
- Test: utöka `privacy-dataflow-regressions.test.ts` så att inget event bär ämne via `category` eller slug för guider/chatt.
- Separat beslut: om offentliga ämnessidors sökvägar ska saneras, och Admin-kontroll av GA4/Ads.

### Förslag 3 – Supabase-säkerhet (P2, konfiguration)

- Slå på läckt-lösenordsskydd (Dashboard, ingen kod).
- Granska `current_user_is_super_admin()`: om den bara behövs i RLS-policyer – `revoke execute … from anon`. Kräver en migration och därför separat beslut.
